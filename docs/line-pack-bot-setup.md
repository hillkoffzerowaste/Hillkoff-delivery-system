# LINE OA ห้องแพ็ค

## สิ่งที่ติดตั้งในโค้ด
- POST /api/line/webhook ตรวจ HMAC บน raw body และรับเฉพาะกลุ่มใน allowlist
- ข้อความแชร์ห้องแพ็คเติม / อัตโนมัติ อ่านรหัสจากบรรทัด งาน:
- /วันนี้, /วันที่ DD/MM/YYYY (รองรับ พ.ศ.), /ออเดอร์ ID, /ช่วยเหลือ
- ค้น orders โดย ID ใช้ deliveryMethod company_driver รวมรายการส่งต่อและส่งสำเร็จ
- วันที่ใช้ chiangmaiRoundDate ก่อน serviceDate รายการไม่มีวันที่ไม่รวมยอดและแจ้งในคำตอบ
- line_pack_receipts เก็บหนึ่งรายการต่อกลุ่มและออเดอร์ด้วย transaction ไม่เขียนสถานะ orders
- line_bot_processed เก็บ event ที่ตอบสำเร็จแล้ว ไม่เก็บข้อความสนทนาทั่วไปหรือ reply token
- รายงานอ่านสถานะปัจจุบัน ไม่ใช่ snapshot สถานะ ณ วันในอดีต

## ตั้งค่า OA
1. เข้า LINE Official Account Manager ด้วยบัญชีเจ้าของ สร้าง OA ชื่อที่เสนอ “Hillkoff ห้องแพ็ค” หรือเลือก OA ภายในที่มีอยู่
2. เปิด Messaging API และเลือก provider ของบริษัท
3. ตั้งค่าฝั่ง server เท่านั้น: LINE_CHANNEL_SECRET, LINE_CHANNEL_ACCESS_TOKEN และ LINE_ALLOWED_GROUP_IDS (groupId คั่นด้วย comma)
4. ตั้ง Webhook URL เป็น https://<โดเมนระบบ>/api/line/webhook เปิด Use webhook และตรวจ Verify
5. เปิด Allow bot to join group chats ปิดข้อความตอบกลับอัตโนมัติที่ชนกับบอท
6. เชิญ OA เข้ากลุ่มที่อนุมัติ ข้อมูลลูกค้าจะตอบให้ทุกคนในกลุ่มนั้นเห็น
7. ส่ง /รหัสกลุ่ม ในกลุ่มที่เชิญ OA แล้ว จากนั้นผู้ดูแลนำรหัสไปตั้ง LINE_ALLOWED_GROUP_IDS คำสั่งนี้คืนเฉพาะ ID กลุ่ม ไม่อ่านข้อมูลออเดอร์
8. deploy หลังตรวจและอนุมัติการนำขึ้น production ตาม AGENTS.md

อย่าวาง secret หรือ access token ในแชทหรือ commit ลง repository

## ตรวจรับก่อนเปิดจริง
- กลุ่มที่ไม่อนุญาต / แชทส่วนตัว / ลายเซ็นผิด ต้องอ่านข้อมูลออเดอร์ไม่ได้
- ข้อความปกติไม่ตอบ ข้อความมีหลายรหัสต้องไม่บันทึก
- ส่งข้อความเดิมซ้ำยอดไม่เพิ่ม และ webhook redelivery หลังตอบสำเร็จไม่ตอบซ้ำ
- วันที่รอบต่างจากวันที่งานต้องรวมเพียงวันเดียว งานส่งสำเร็จยังอยู่ในยอด
- แชร์ก่อนกดยืนยันในแอป: บอทแจ้งสถานะที่ยังไม่อัปเดต จากนั้น /วันนี้ ต้องแสดงสถานะใหม่
- ใช้กลุ่มทดสอบตรวจการส่งข้อความจริงและข้อความ / ที่คัดลอกจากหน้าเว็บ

## ข้อจำกัดที่ต้องทราบ
- ยังต้องสร้าง/ตั้งค่า OA และเชื่อม production จึงใช้งานจริงได้
- คำตอบเป็นสถานะล่าสุด; การถอน/แก้ข้อความ LINE ไม่ได้ยกเลิกการรายงานออเดอร์
- เมื่อ reply API สำเร็จแต่การบันทึก processed ล้มเหลว การ retry อาจเจอ reply token ใช้แล้ว: receipt ไม่ซ้ำแต่คำตอบไม่รับประกันซ้ำได้ ควรใช้ /วันนี้ ตรวจซ้ำและติดตาม webhook error
- การอ่านรายงานจำกัด 5,000 รายการต่อ query เกินแล้วแจ้งให้ใช้ระบบหลัก
- บัญชีเก่าที่ไม่มี serviceDate/chiangmaiRoundDate ไม่รวมในรายวัน ไม่เดาวันจาก updatedAt
