# Store Operations Dashboard

วันที่ 11 พฤศจิกายน 2569 · ผู้ใช้อนุมัติพัฒนา push และ deploy ต่อจากแบบ

## รูปแบบที่เลือก

ใช้กราฟวงกลมโดนัทเป็นส่วนหลักของหน้า ให้ยอดรวมอยู่กลางวง พร้อมรายการสีและจำนวนที่กดเปิดรายการจริงได้ โทน teal เดิมของระบบ กราฟไม่ใช้สีเป็นคำอธิบายเพียงอย่างเดียว และกดด้วยคีย์บอร์ดได้

| มุมมอง | เนื้อหาหลัก |
| --- | --- |
| ภาพรวมทีม | เอกสารตามประเภท เคสเกิดในช่วงตามสถานะปัจจุบัน การรับสินค้า และรายการที่ต้องติดตาม |
| รายบุคคล | เลือกพนักงานแล้วดูโดนัทเอกสาร เคสที่รับผิดชอบ และกิจกรรมปิดที่ตนเป็นผู้กระทำ กดเจาะรายการจากกราฟได้ |
| เคสและสินค้าค้าง | รับครบ/ไม่ครบ รายการค้าง แหล่งรอ supplier/คลัง PO ETA และผู้ติดตาม ตามทะเบียนเคสเดิม |
| วิเคราะห์ | ประเภท/สาเหตุปัญหา กิจกรรมปิด และความครบถ้วนของข้อมูลการรับ |

ตัวกรองวันที่ สาขา พนักงาน และประเภทเอกสารใช้ชุดเดียวกันภายในแดชบอร์ด รายงานเดิม ข้อความ LINE บันทึกงาน และแผนงานยังเปิดได้ โดยโหลดเมื่อผู้ใช้เปิดดู

## ความหมายตัวเลข

- เอกสารนับเป็นเอกสารยืนยันตามวันเอกสาร ไม่เอายอด createdAt จากรายงานเก่ามารวมเป็นฐานเดียวกัน
- เคสเกิดในช่วงเป็น cohort ตามวันพบ/เริ่มเคส และแสดงสถานะปัจจุบันของเคสชุดนั้น
- เคสค้างสะสมเป็นสถานะขณะนี้ข้ามช่วงวันที่ จึงไม่ใช่ยอด ณ สิ้นวันในอดีต
- กิจกรรมปิดนับเหตุการณ์ตามวันและ actor ในประวัติ รองรับเปิดใหม่แล้วปิดซ้ำ ไม่โอนเครดิตให้เจ้าของเคสโดยอัตโนมัติ
- โดนัทการรับใช้จำนวนรายการสินค้า แยกรับครบ รับบางส่วน ยังไม่รับ และยุติด้วยการยกเลิก ส่วนข้อมูลไม่พอแสดงแยก ไม่รวมปริมาณต่าง SKU หรือหน่วย
- เอกสาร เคส รายการ และกิจกรรมไม่รวมเป็นโดนัทวงเดียวกัน

## ขอบเขตการใช้งาน

ใช้ canonical store_cases และ API เดิมเป็นฐาน ไม่สร้างทะเบียนปัญหาคู่ขนาน แสดง supplier/PO/ETA ตามที่บันทึกใน tracker ข้อมูลนี้ยังไม่ใช่ stock หรือ PO ที่เชื่อมต่อจากระบบอื่น ไม่สร้าง SLA คะแนนพนักงาน หรือชั่วโมงทำงานจากจำนวนเอกสาร

การคีย์ใบโอนและใบขอโอนย้อนหลังคงใช้ flow เดิม ไม่สร้างเอกสารใบเบิกอีกชนิดหนึ่ง บทบาทและสิทธิ์เดิมคงเป็นข้อกำหนดการเข้าถึงข้อมูล

ต้นแบบ operations-center.html ใช้ข้อมูลตัวอย่างเพื่อสื่อรูปแบบหน้าจอเท่านั้น ตรรกะที่ต้องแก้จากต้นแบบระบุใน business-review.md การปล่อยจริงใช้ผลตรวจโค้ดและเทสต์ตาม release-acceptance.md
