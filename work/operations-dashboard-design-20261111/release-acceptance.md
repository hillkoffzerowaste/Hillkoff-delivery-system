# เกณฑ์ตรวจรับ Store Operations Dashboard

วันที่ 11 พฤศจิกายน 2569 ผู้ใช้อนุมัติพัฒนาต่อจากแบบ พร้อม push และ deploy

- ภาพรวมทีมและหน้ารายบุคคลใช้กราฟวงกลมโดนัทเป็นองค์ประกอบหลัก โทน teal ของระบบ
- กราฟและคำอธิบายกดตรวจรายการฐานจริงได้ ไม่ใส่ข้อมูลตัวอย่างในระบบจริง
- เอกสาร เคส กิจกรรมปิด และรายการสินค้าต้องแยกหน่วย รวมยอดโดนัทจากฐานเดียวกัน
- เคสเกิดในช่วงแสดงสถานะปัจจุบัน ส่วนค้างสะสมระบุชัดว่าเป็นปัจจุบัน ไม่ใช่ยอด ณ สิ้นวันย้อนหลัง
- ผลงานผู้ปิดเคสใช้ผู้กระทำในประวัติ ไม่อนุมานจากเจ้าของเคส
- รายการรับครบ รับบางส่วน ยังไม่ได้รับ ยกเลิก และไม่มีข้อมูล ต้องไม่ทำให้ยอดครบผิด
- ดูแหล่งรอ supplier/warehouse, PO, ETA ตามข้อมูลที่บันทึก ไม่อ้างเป็น stock หรือ PO ที่เชื่อมต่อจริง
- การคีย์ใบโอนและใบขอโอนย้อนหลัง รวมทั้งโมดูลเดิม เข้าถึงและใช้งานได้
- ตรวจ loading, error, empty, stale requests, unknown owner และมือถือแคบ
- ก่อน commit: lint, unit tests, production build และตรวจ UI บนเบราว์เซอร์จริงแบบ headless
- ตรวจ diff เองและ reviewer; ไม่เปลี่ยนสิทธิ์ Rules/indexes หรือข้อมูลถาวร
- หลัง push: ตรวจ commit ของ build, rollout สำเร็จ และ traffic 100% ก่อนแจ้ง deploy สำเร็จ

เอกสาร workflow.md เป็นแนวคิดระยะแรก หากแนวจัดวางขัดกับคำสั่งล่าสุด ให้ใช้ข้อกำหนดกราฟและโดนัทเป็นหลักตามไฟล์นี้และต้นแบบ operations-center.html
